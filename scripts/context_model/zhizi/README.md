# Shunshou-Zhizi training scripts (顺手·知字)

Training, evaluation, and export code for **Shunshou-Zhizi** (`shunshou-zhizi-30m`), the small character-level model that re-ranks candidates of the Zhizi pinyin input method.

- The model itself is published separately: <https://huggingface.co/DabbleCove/shunshou-zhizi-30m> (CC BY-SA 4.0).
- The **model card on that page is the authoritative source for training data, evaluation numbers, and licensing**; this README explains the code and links there instead of restating those details.
- How the input method uses the model (three build-time tiers): [docs/public/MODEL.md](../../../docs/public/MODEL.md). Project overview: [docs/public/README.md](../../../docs/public/README.md).

## Work directory

Scripts in this directory do not write next to themselves at runtime. They read and write a work directory selected by the `ZHIZI_WORK` environment variable (default: `ime_context_model/` under the repository checkout). Corpora, synthesis batches, checkpoints, and exported models live there and are not committed to Git.

## Requirements

- Python 3 with `torch` and `numpy` (training, evaluation, export) and `pypinyin` (homophone-set and phrase tools). The repository ships no requirements file for these scripts; prepare the dependencies yourself. Version numbers used for the release are not pinned in this repository.
- Core ML export: macOS with `coremltools` and the Xcode command-line tools (`xcrun coremlcompiler`).
- ONNX export: `torch.onnx.export` (ships with PyTorch) plus `onnxruntime` for the agreement check.
- Compute: any machine that runs PyTorch; the training scripts auto-select CUDA / Apple MPS / CPU. `gpu_run.sh` automates the full run on a CUDA host.
- Data: **the corpora are not in this repository.** Prepare them yourself; the model card lists the public sources and licenses used for the released model. `prepare_corpus.py` reads a normalized JSONL layer of licensed public sources (the expected layout is a constant at the top of the script). Synthetic data is generated by LLM backends and is AI-generated text (labeled as such in the corpus manifest); generation calls local CLIs or an HTTPS API and may incur cost.

## Pipeline

1. **Corpus**: `prepare_corpus.py` (public sources → per-source text, character vocabulary, license manifest) → `tokenize_corpus.py` (uint16 token streams).
2. **Synthetic colloquial data**: `synth_batches.sh` drives `synth_generate.py` in ~1M-character batches, each gated by `synth_check.py`; `prepare_synth.py` folds finished batches into the corpus as the `synth` source. `after_synth.sh` builds the combined corpus, the homophone set, and a training bundle in one go.
3. **Training**: `train.py` (pretraining with per-source sampling weights) → `make_homophone_set.py` (homophone-choice questions built from the IME's own Rime dictionaries) → `train_homophone.py` (fine-tune whose objective matches deployment scoring). `gpu_run.sh` chains these on a CUDA host; `gpu_run_v2.sh` is the variant used for the released weights (two fine-tunes that are later averaged — see the model card).
4. **Export**: `export_coreml.py` (Core ML fp16 for macOS) and `export_onnx.py` (ONNX for Windows and other platforms), each with a first-pick agreement check against the PyTorch reference.
5. **Gates and checks**: `check_host_alignment.py` runs the exported Core ML model through the production Swift scorer on a public synthetic case set (gates: ≥ 99% first-pick agreement, rerank p95 ≤ 8 ms; thresholds are in the script). `memorization_check.py` is the release privacy check described in the model card (membership, extraction, free sampling); it needs the private training rows and control checkpoints, so it only runs on a machine that has them.

## Scripts

| Script | What it does |
|---|---|
| `model.py` | `ZhiziLM`: small character-level causal LM (GPT-2-style blocks, learned positions, tied embeddings); presets `tiny`/`30m`/`50m`; checkpoint save/load with the vocabulary embedded |
| `prepare_corpus.py` | Build the pretraining corpus from a normalized JSONL layer of licensed public sources (Wikipedia, UN parallel corpus, asap, Tatoeba): per-source train/valid text, character vocabulary, license manifest |
| `tokenize_corpus.py` | Encode corpus text files into uint16 token streams, `<bos>` between paragraphs |
| `synth_generate.py` | Generate synthetic colloquial / work-chat / Chinese-English text with LLM backends; per-call records, failure counting, character targets |
| `synth_check.py` | Per-batch quality gate (failure rate, duplicates, volume); exit 1 stops the batch loop |
| `synth_batches.sh` | Run synthesis batch by batch; skip batches with a `DONE` marker; stop at the first failed quality check |
| `prepare_synth.py` | Fold finished synthesis batches into a corpus directory as the `synth` source and update the manifest |
| `after_synth.sh` | After synthesis: build the combined corpus, build the homophone set, pack a code + data bundle for a CUDA host |
| `train.py` | Pretraining with per-source sampling weights, warmup + cosine learning rate, periodic validation, `best.pt` / `last.pt` checkpoints |
| `make_homophone_set.py` | Homophone-choice training rows from the IME's shipped Rime dictionaries (same reading → candidate group), readings via `pypinyin`; `--rime` selects another dictionary directory |
| `train_homophone.py` | Stage-2 fine-tune: softmax over candidate scores (sum of the candidate's character log-probabilities) with a mixed LM loss |
| `gpu_run.sh` | One-command pretrain → homophone fine-tune → pack on a CUDA host |
| `gpu_run_v2.sh` | Variant used for the released run: one pretraining plus two fine-tunes that are later weight-averaged (see the model card) |
| `export_coreml_spike.py` | The static scorer graph used for Core ML export, plus latency and precision benchmarks across Core ML compute units |
| `export_coreml.py` | Export a checkpoint to the Core ML model the macOS input method ships (`zhizi30m_v2.mlpackage` / `.mlmodelc`, `itos.json`), with an optional agreement check |
| `export_onnx.py` | Export to ONNX (dynamic batch and length) and check agreement on the public synthetic cases |
| `check_host_alignment.py` | Parity gate: exported Core ML model vs PyTorch reference through the Swift production harness (public synthetic set; a local held-out check only if private records exist); prints PASS/FAIL lines |
| `test_check_host_alignment_batching.py` | Unit tests for the batching logic of `check_host_alignment.py` (`python -m unittest test_check_host_alignment_batching`) |
| `mine_phrases.py` | Mine colloquial phrase candidates from corpus n-grams (frequency + branching entropy) into a review list, and measure how well they cover raw-pinyin fallbacks recorded locally |
| `gen_phrases.py` | Generate targeted colloquial phrases around hinge words via an LLM, for the IME phrase layer |
| `judge_phrases.py` | Second-pass LLM filter that keeps phrase candidates people would type in one go |
| `memorization_check.py` | Release privacy check (membership inference, extraction, free sampling) comparing the published weights with control checkpoints; outputs stay outside Git |

Several further scripts are experiments over **private, locally recorded typing events** (offline policy estimates, adjudicated scoring, personal fine-tune / LoRA adaptation, training-row preparation). They read a local events file that is not part of the repository, run only on a machine holding it, and are not part of the public reproduction path.

## Evaluation and the released model

The scripts score homophone choices exactly the way the input method does: a candidate's score is the sum of its character log-probabilities after the preceding text. The released model's evaluation protocol, numbers, and known limitations are documented in the model card and not restated here.

To *use* the model rather than train it: the input method fetches the published Core ML build with `scripts/context_model/fetch_public_model.py` — see [docs/public/MODEL.md](../../../docs/public/MODEL.md).

## Notes and limitations

- This repository contains neither corpora nor checkpoints; reproducing training starts with data preparation (the model card lists what the released model was trained on).
- Synthetic data is AI-generated text, labeled as such; generating it calls LLM backends (local CLIs or an HTTPS API) and may incur cost.
- Compiled Core ML artifacts embed a compiler-generated conversion timestamp and UUIDs, so they are not byte-reproducible (see [docs/public/README.md](../../../docs/public/README.md)).
- The homophone-set builder defaults to the Rime resources of an installed IME; point `--rime` at another dictionary directory to work without one.

# 顺手·知字训练脚本（Shunshou-Zhizi）

本目录是**顺手·知字**（`shunshou-zhizi-30m`）的训练、评测与导出代码。该模型是知字拼音输入法用来给候选排序的小型字级模型。

- 模型单独发布：<https://huggingface.co/DabbleCove/shunshou-zhizi-30m>（CC BY-SA 4.0）。
- 该页面的**模型卡是训练数据、评测数字与授权的权威来源**；本 README 只解释代码，细节链接到模型卡，不复述。
- 输入法如何接入模型（三种构建档位）：[docs/public/MODEL.md](../../../docs/public/MODEL.md)。项目总览：[docs/public/README.md](../../../docs/public/README.md)。

## 工作目录

脚本运行时不写本目录自身，而是读写由环境变量 `ZHIZI_WORK` 指定的工作目录（缺省为仓库内的 `ime_context_model/`）。语料、合成批次、checkpoint 与导出产物都在那里，不入 Git。

## 环境与数据

- Python 3，以及 `torch`、`numpy`（训练 / 评测 / 导出）和 `pypinyin`（同音题集与短语工具）。仓库没有这些脚本的 requirements 文件，依赖请自行准备；发布时用的版本号没有在仓库里固定。
- Core ML 导出：macOS 上的 `coremltools` 与 Xcode 命令行工具（`xcrun coremlcompiler`）。
- ONNX 导出：PyTorch 自带的 `torch.onnx.export`，另需 `onnxruntime` 做一致性检查。
- 算力：任何能跑 PyTorch 的机器都可以；训练脚本自动选择 CUDA / Apple MPS / CPU。`gpu_run.sh` 可在 CUDA 主机上一键跑完整流程。
- **语料不在仓库里**，需要自行准备；发布模型所用的公开来源与授权见模型卡。`prepare_corpus.py` 读取许可明确的公开来源的规范化 JSONL 层（期望的目录结构是脚本顶部的常量）。合成数据由大模型后端生成，属于 AI 生成文本（语料 manifest 里有标注）；生成需要调用本地 CLI 或 HTTPS API，可能产生费用。

## 流程

1. **语料**：`prepare_corpus.py`（公开来源 → 分来源文本、字表、许可 manifest）→ `tokenize_corpus.py`（uint16 token 流）。
2. **合成口语数据**：`synth_batches.sh` 按约 100 万字一批驱动 `synth_generate.py`，每批过 `synth_check.py` 质检；`prepare_synth.py` 把完成的批次并进语料作为 `synth` 源。`after_synth.sh` 一次性完成合并语料、同音题集与训练包。
3. **训练**：`train.py`（按来源加权采样的预训练）→ `make_homophone_set.py`（用输入法自带 Rime 词库的同音组出选择题）→ `train_homophone.py`（训练目标对齐部署打分的微调）。`gpu_run.sh` 在 CUDA 主机上串起这三步；`gpu_run_v2.sh` 是发布权重用的变体（两个微调之后取平均，见模型卡）。
4. **导出**：`export_coreml.py`（macOS 用 Core ML fp16）与 `export_onnx.py`（Windows 等平台用 ONNX），都带与 PyTorch 参考的首选一致性检查。
5. **门禁与检查**：`check_host_alignment.py` 把导出的 Core ML 模型放进 Swift 生产评分器，在公开合成用例上比对（门禁：首选一致率 ≥ 99%、重排 p95 ≤ 8 ms，阈值在脚本里）。`memorization_check.py` 是模型卡所述的发布前隐私检查（成员推断、续写抽取、自由采样）；它需要私有的训练行与对照 checkpoint，只在有这些文件的机器上能跑。

## 脚本一览

| 脚本 | 作用 |
|---|---|
| `model.py` | `ZhiziLM`：小型字级因果语言模型（GPT-2 式块、学习式位置编码、共享嵌入）；`tiny`/`30m`/`50m` 三档；checkpoint 保存 / 加载时词表随模型一起走 |
| `prepare_corpus.py` | 从许可明确的公开来源（维基百科、联合国平行语料、asap、Tatoeba）的规范化 JSONL 层建预训练语料：分来源 train/valid 文本、字表、许可 manifest |
| `tokenize_corpus.py` | 把语料文本编码成 uint16 token 流，段落之间插 `<bos>` |
| `synth_generate.py` | 用大模型后端生成口语 / 工作聊天 / 中英混排合成文本；逐次调用记录、失败计数、字数目标 |
| `synth_check.py` | 每批质检（失败率、重复率、产量）；退出码 1 会停掉批次循环 |
| `synth_batches.sh` | 逐批跑合成；带 `DONE` 标记的批次跳过；质检失败即停 |
| `prepare_synth.py` | 把完成的合成批次并进语料目录作为 `synth` 源，并更新 manifest |
| `after_synth.sh` | 合成结束后：建合并语料、建同音题集、给 CUDA 主机打包代码 + 数据 |
| `train.py` | 预训练：按来源加权采样、warmup + 余弦学习率、定期验证、`best.pt` / `last.pt` checkpoint |
| `make_homophone_set.py` | 从输入法自带的 Rime 词典（同读音 → 候选组）出同音选择题，读音用 `pypinyin`；`--rime` 可指定其他词典目录 |
| `train_homophone.py` | 第二阶段微调：对候选得分（候选各字对数概率之和）做 softmax，混入普通 LM 损失 |
| `gpu_run.sh` | CUDA 主机上一条命令：预训练 → 同音微调 → 打包 |
| `gpu_run_v2.sh` | 发布权重用的变体：一次预训练加两个微调，之后权重取平均（见模型卡） |
| `export_coreml_spike.py` | Core ML 导出所用的静态评分器图，以及在各种 Core ML 计算单元上的延迟与精度基准 |
| `export_coreml.py` | 把 checkpoint 导出成 macOS 输入法随包发布的 Core ML 模型（`zhizi30m_v2.mlpackage` / `.mlmodelc`、`itos.json`），可选一致性检查 |
| `export_onnx.py` | 导出 ONNX（动态 batch 与长度），并在公开合成用例上做一致性检查 |
| `check_host_alignment.py` | 一致性门禁：导出的 Core ML 模型与 PyTorch 参考经 Swift 生产评分器比对（公开合成用例集；仅当本机有私有记录时另做本地留出检查）；输出 PASS/FAIL 行 |
| `test_check_host_alignment_batching.py` | `check_host_alignment.py` 分批逻辑的单元测试（`python -m unittest test_check_host_alignment_batching`） |
| `mine_phrases.py` | 从语料 n-gram（词频 + 分支熵）挖口语短语候选出评审清单，并测量它们对本机记录的裸拼音兜底输入的覆盖 |
| `gen_phrases.py` | 围绕枢纽词用大模型定向生成口语短语，供输入法短语层用 |
| `judge_phrases.py` | 第二道大模型过滤：保留人们会一口气打出的短语候选 |
| `memorization_check.py` | 发布前隐私检查（成员推断、抽取、自由采样），对比发布权重与对照 checkpoint；产物留在 Git 之外 |

另有若干脚本是对**本机私有打字记录**的离线实验（策略估计、裁定评分、个人微调 / LoRA 适配、训练行整理）。它们读取仓库之外的本机事件文件，只在有该文件的机器上运行，不属于公开复现路径。

## 评测与发布模型

这里的脚本给同音选择打分的方式与输入法完全一致：候选得分 = 前文之后候选各字对数概率之和。发布模型的评测口径、数字与已知局限见模型卡，本 README 不复述。

只想**用**模型而不训练：输入法用 `scripts/context_model/fetch_public_model.py` 获取已发布的 Core ML 产物，见 [docs/public/MODEL.md](../../../docs/public/MODEL.md)。

## 已知限制与注意事项

- 仓库不含语料和 checkpoint；复现训练从准备数据开始（发布模型用了哪些数据见模型卡）。
- 合成数据是 AI 生成文本，已有标注；生成需要调用大模型后端（本地 CLI 或 HTTPS API），可能产生费用。
- 编译出的 Core ML 产物内嵌编译器生成的转换时间戳与 UUID，无法逐字节复现（见 [docs/public/README.md](../../../docs/public/README.md)）。
- 同音题集默认读已安装输入法的 Rime 资源目录；用 `--rime` 指向其他词典目录即可脱离安装环境工作。
